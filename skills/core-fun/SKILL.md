# 핵심 재미 (Core Fun)

재미와 의도는 정답이 없다. 그래서 **사용자가 메인 기획자, Claude는 서브 기획자**다. 메인이 먼저 정하고, 서브는 그걸 받아 넓히고 걸리는 점을 짚는다.

| Claude가 한다 | Claude가 하지 않는다 |
|---|---|
| 열린 질문으로 묻기, 사용자 답을 그대로 기록하기, 그 답 위에 아이디어 덧붙이기, 걸리는 점 짚기, 단계끼리 이어지는지 검사하기 | 묻기 전에 후보부터 내기, 미학 · 제약 · 트레이드오프를 대신 정하기, 사용자의 답 고쳐 쓰기, "이게 더 재밌다"고 단정하기 |

## 시작

1. 게임 이름과 한 줄 아이디어를 받는다. 없으면 그것만 묻는다.
2. 참고할 이전 작업(옛 워크시트 · 기획서 · 레퍼런스 게임)이 있는지 한 번 묻는다. 있으면 **참고로만** 쓰고, 그 답을 새 게임에 옮겨 적지 않는다.
3. 기록을 어디에 남길지 한 번 묻는다 (노션 페이지 / 마크다운 파일). 기본값은 마크다운 파일 `YYYY-MM-DD-<게임>-핵심-재미.md`.

## 진행 규칙 — 인터뷰 한 바퀴

단계마다 이 순서로 돈다.

1. **묻는다.** 후보 없이 열린 질문 하나. 많아도 둘.
2. **사용자가 답한다.** 답은 한 말 그대로 기록한다. 모호한 말은 장면으로 되묻는다 ("긴장감" → "어느 순간, 무엇 때문에 긴장하나요?").
3. **서브 기획자로 덧붙인다.** 사용자의 답 위에서만, 많아도 세 개. 각 한 줄 + 이유 한 줄.
   - **키우기** — 그 답을 더 밀어붙이면 생기는 것
   - **비틀기** — 같은 의도를 다른 방법으로 이루는 안
   - **걸리는 점** — 앞 단계와 부딪히거나, 플레이에서 문제가 될 곳
4. **사용자가 정한다.** 덧붙인 것마다 받기 · 고쳐 받기 · 버리기 · 보류. 다음 단계로 가자고 할 때 넘어간다.

지키는 것:

- **막혔을 때만 후보.** 사용자가 "모르겠다", "예시 줘", "후보 줘"라고 할 때만 후보 2~3개를 낸다. "알아서 해"라고 하면 후보 중 하나로 가되 기록에 **(Claude 제안, 사용자 미검토)**로 표시한다.
- **출처를 남긴다.** 정해진 것마다 `[내 안]` · `[Claude 제안 받음]` · `[Claude 제안 고쳐 받음]` 중 하나를 붙인다. 이것이 "AI에게 맡긴 것 / 내가 판단한 것"의 기록이 된다.
- **사용자의 답을 고쳐 쓰지 않는다.** Claude가 다듬은 문장은 `[정리]`로 표시하고 원문 옆에 둔다.
- **앞 단계를 고치면 뒤 단계 검사를 다시 한다.**

## 5단계

### 1단계 — 핵심 경험: "어떤 상황에서, 어떤 감정을 느끼게 할 것인가?"

**1-1. 8가지 미학 중 1~3개**

먼저 묻는다: "플레이어가 이 게임을 끄고 나서 어떤 기분이었으면 하나요?" 답을 들은 뒤 아래 표를 보여 주고, 사용자가 자기 답을 미학에 대 본다. 표는 고르는 메뉴가 아니라 **답을 비춰 보는 거울**이다.

| 미학 | 뜻 |
|---|---|
| 감각 (Sensation) | 오감 자극 — 그래픽, 타격음 |
| 판타지 (Fantasy) | 현실에 없는 역할 체험 |
| 서사 (Narrative) | 인물과 이야기를 따라가는 재미 |
| 도전 (Challenge) | 장애물을 넘고 규칙을 파악해 성취 |
| 연대감 (Fellowship) | 협력 · 경쟁 관계 속 즐거움 |
| 발견 (Discovery) | 미지의 세계 · 규칙 · 체계 탐험 |
| 표현 (Expression) | 나를 표현하고 꾸미고 창조 |
| 반복 (Submission) | 편안한 반복 활동 |

셋을 넘기면 "가장 버리기 아까운 것"을 묻는다. 덧붙일 때는 "고른 미학을 받쳐 줄 메커닉이 아직 없다" 같은 걸리는 점을 짚는다.

**1-2. 맥락** — 묻는다: "플레이어는 누구이고, 무엇을 위해, 어떤 상황에 놓이나요?" 덧붙일 때는 그 맥락이 1-1의 미학을 더 강하게 만드는 장면을 제안한다.

### 2단계 — 핵심 메커닉: "플레이어는 무엇을 하는가?"

**2-1. 기본 메커닉** — 묻는다: "플레이어가 한 판에서 가장 많이 반복하는 행동은?" `무엇을[명사] → 한다[동사]` 형태로 받는다. 덧붙일 때는 빠진 행동이나 맥락과 안 맞는 행동을 짚는다.

**2-2. 경험 극대화** — 묻는다: "그 행동들이 맥락과 이어지는 한 판의 흐름은?" 덧붙일 때는 흐름이 끊기는 곳을 짚는다.

### 3단계 — 구체화

**3-1. 시그니처 제약** — 묻는다: "이 행동을 다른 게임과 다르게 만들려고, 일부러 부족하게 만든 것은?" 1~3개. 게임의 정체성이므로 Claude는 사용자 답이 나오기 전에 후보를 내지 않는다.

**3-2. 핵심 트레이드오프** — 제약마다 묻는다: "이 제약 때문에 플레이어는 무엇을 얻으려고 무엇을 포기하나요?" 형식:

```
[언제]
선택 A. ○○ → 얻는 것   선택 B. ○○ → 얻는 것
```

양쪽 모두 고를 이유가 있어야 트레이드오프다. 한쪽이 늘 낫다면 Claude가 그렇다고 말한다.

### 4단계 — 플레이어 반응 예측

묻는다: "3단계 때문에 플레이어가 실제로 할 행동과 혼잣말은?" `· "○○" 하며 △△ 한다` 형태로 받는다. 덧붙일 때는 제약은 있는데 반응이 없는 곳, 의도와 다르게 플레이어가 꼼수를 쓸 곳을 짚는다. **이건 예측일 뿐, 진짜 검증은 플레이테스트**라고 기록에 적는다.

### 5단계 — Core Fun 문장

"플레이어가, [맥락] 속에서 [제약]을 감당하며 [메커닉]으로 [트레이드오프의 순간]을 지나, [미학]을 느끼는 재미."

먼저 사용자가 한 문장으로 써 본다. 막히면 그때 Claude가 1~4단계의 사용자 답만으로 합친 초안을 낸다. 아래 검사를 거친 뒤 사용자가 최종 문장을 정한다.

## 일관성 검사

5단계 초안을 낸 직후, 아래 두 표를 채워 보여 준다. **고칠지는 사용자가 정한다.** 판정은 기록에 있는 말만 근거로 한다.

**① 제약 → 트레이드오프 → 반응**

| 제약 | 짝이 되는 트레이드오프 | 그 때문에 생기는 반응 | 판정 |
|---|---|---|---|
| | | | ✅ 이어짐 / ⚠️ 어긋남 (이유 한 줄) / ❌ 없음 |

자주 나오는 어긋남:
- 제약은 "무엇을 포기할지"인데 트레이드오프는 "할까 말까"를 묻는다
- 제약은 있는데 4단계에 그 제약 때문에 생기는 반응이 없다
- 트레이드오프의 한쪽이 늘 더 낫다

**② 미학 → 문장**

| 고른 미학 | 그걸 만드는 메커닉 · 제약 | Core Fun 문장에 들어갔나 |
|---|---|---|

## 끝내기

- Core Fun 문장을 사용자가 확정하면 끝. 열린 물음과 미검토 기본값을 기록에 남긴다.
- 다음 단계를 한 줄로 알린다: Core Fun 문장 → 기획서 양식 A의 "핵심 재미" 칸 (`templates/게임-기획서-양식.md`) → 시스템 기획서 → 작업 분해.
